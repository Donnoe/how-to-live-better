# 设计 Spec · 高性价比人生指南阅读页改版

> 三个设计方向的**唯一共同输入**。各方向独立工作、互不参考。
> 本文件由 Phase 1-3 产出，Phase 4 三套逻辑共用。

---

## 1. 项目是什么

改造一个**已上线的开源项目阅读页**：https://cdyforever.github.io/how-to-live-better/

- 内容源：开源书《高性价比人生指南》，34 节、654 条建议，作者 eternity4719（Unlicense 公有领域）
- 现有形态：`build.py` 生成的单文件 HTML（2.3MB），零外部资源、可离线、可打印、GitHub Pages 托管
- 用户已 fork 到 `github.com/Donnoe/how-to-live-better`，本次改版推送到该 fork
- **我们不改内容，只改「读起来的样子」**：「说人话」「收益」「来源」等全部原文照搬，一字不改

### 现状的关键事实（三个方向都必须尊重）

| 事实 | 影响 |
|---|---|
| 「说人话」平均 101 字，最长 138 字 | 每日十条模块的卡片必须能容下一段话，不能只放一行标题 |
| 条目标题最长 71 字（多为分号并列的两件事） | 卡片标题不能假设「一行放得下」 |
| 证据等级 A429 / B174 / C51 | A 级占 66%，可以安全用作默认推荐池的主体 |
| 全站 654 条、1570 条文献外链 | 搜索、筛选、目录等既有功能必须全部保留 |
| 原页面已有明暗主题、搜索、目录联动、回到顶部、打印样式 | 改版是**视觉+易读性**升级，不是重做信息架构 |

## 2. 目标受众与使用场景

**两类人，同一页面：**

1. **手机随手翻**（主场景，约 70%）——通勤、睡前、排队。竖屏，单手，只看「说人话」那一栏，最多看 2-3 分钟。**这是「可爱」的主战场。**
2. **电脑认真查**（次场景，约 30%）——要核实一条建议的证据来源、要看成本收益的完整数字、按关键词定位。**这是「易读」的主战场。**

情感基调关键词：**温柔、可靠、不说教、有一点俏皮但不轻浮**。

潜在期待（用户没说但很可能在意）：
- 打开第一眼就想读，而不是看到一份「文档」
- 手机上不会因为字小、留白少而读不下去
- 「每天十条」能替代刷朋友圈的碎片时间，且内容是有出处的真东西
- 改完之后仍然能**打印出来当纸质资料**（原页面支持打印，作者在用这个能力）

## 3. 核心信息与内容要点

### 3.1 新增模块：首页「每日十条」（**本次最重要的新增功能**）

位置：页面**最顶部**，在原顶栏之下、所有章节之上。这是首页的视觉锚点。

行为要求：

| 要求 | 说明 |
|---|---|
| **每天固定十条** | 同一天内刷新页面，十条不变（用日期做随机种子，同种子必得同结果） |
| **跨天自动更新** | 到了第二天，自动换一批新的十条，用户不需要做任何操作 |
| **可手动换一批** | 提供「换一批」按钮，用户想要更多时能主动再摇十条 |
| **优先高性价比** | 优先从「成本=0 或少 + 收益=大」的条目里抽，让每天看到的最有用 |
| **每条要能读完** | 展示「说人话」全文（这是最有价值的部分），不是截断的半句 |
| **点进去能跳原文** | 每条可跳到该条在正文中的位置（锚点 `#s1-1`），或展开看详情 |
| **标注可信度** | 每条显示证据等级（A/B/C），让用户知道这条有多硬 |
| **不打扰** | 已读过的状态可记忆（localStorage），但**不要**做打卡、连续天数、进度条这类游戏化压力 |

**设计上的核心判断**：这个模块的成败不在"抽十条"，而在**让用户愿意读完这十条**。所以卡片必须为 100 字左右的中文段落设计，不是为标题设计的。

### 3.2 既有内容的呈现（保持信息量，只升级可读性）

- 顶栏：标题、搜索、筛选（全部/只看 A 级/只看说人话）、明暗切换、计数
- 左侧目录：34 节 + 654 条，带性价比色点，滚动联动
- 卡片：编号、标题、证据等级/性价比/成本标签、说人话、成本/收益/备注、来源（可折叠）

## 4. 输出格式与尺寸（硬要求）

- **纯 HTML + CSS + 少量原生 JS，单文件，零外部资源**（这是原项目的硬约束：不许有 CDN、不许外链字体、不许 fetch 数据，双击就能开、断网也能读）
- 三个方向**必须是完整可交互的 HTML 文件**，不是静态效果图、不是截图
- 必须内建一个明暗主题切换，且两套主题都好看
- 演示内容用**真实数据**（从 /tmp/hltb.json 取，禁止 Lorem ipsum、禁止编造条目）

### 设计稿的展示范围

每版只需做**两个视口的代表区**，不要做完整 654 条（那是实现阶段的事）：

1. **手机视图（390×844）**：顶栏 + 每日十条模块 + 2 张正文卡片
2. **桌面视图（1440×900）**：顶栏 + 每日十条模块 + 左侧目录 + 2 张正文卡片

做法：写一个 HTML，用容器查询或 JS 切换模拟手机形态也可以，但**必须能截出手机版和桌面版两张不同的图**。

## 5. 已知约束与禁忌

### 5.1 硬约束（违反即失败）

- **零外部资源**：不许 `<link>` 字体、不许 CDN、不许 base64 大图、不许任何网络请求
- **字体只能用系统字体栈**：`PingFang SC` / `Hiragino Sans GB` / `Microsoft YaHei` / `system-ui` / 宋体等
  - ⚠️ 这意味着**不要设计任何依赖特定字形的方案**（比如依赖某个手写体、衬线体的特色）
  - macOS 上有 PingFang SC，Windows 上是微软雅黑，两边都要不丑
- **正文可读性硬底线**：正文 ≥15px（中文正文建议 16-17px）、行高 1.75-1.9、一行不超过 36 个汉字、对比度 ≥4.5:1
- **能打印**：@media print 下模块不能崩，不能浪费整页纸
- **手机 320px 宽不横向滚动**
- 保留原有的搜索、筛选、目录联动、明暗切换功能（可以在视觉上重做，不能删）

### 5.2 内容禁忌

- 不改一个字的内容（「说人话」等是原文摘录，改了就失去出处可信度）
- 不编造数据、不造 stats 装饰
- 不用 emoji 当图标（这是中文站点的 AI 味重灾区）

### 5.3 审美禁区（不要做）

- 紫粉渐变 + 玻璃拟态（2024 年后烂大街的 AI 页模板）
- 大片死白 + 极小字号（"安静派"做过头）
- 每个标题配一个图标
- 圆角+左彩条卡片（2020-2024 Material/Tailwind 味）
- 用 emoji 当装饰

## 6. 情感基调的量化边界

「可爱」这件事在这个项目上有内在矛盾：内容是「死亡率、癌症、法律红线」，用户群是想活得明白的成年人。**做幼稚了会不尊重内容，做严肃了就不是"更可爱"。**

判断标准：
- ✅ 可爱 = 柔软的配色、圆润但不幼稚的形状、留白的呼吸感、一点点俏皮的措辞和微交互
- ❌ 幼稚 = 卡通字体、糖果高饱和、表情符号、拟声词、「呀～」「哦～」这类语气词

## 7. 视觉母题假设（form 的种子）

内容自带一个非常强的母题，**它只属于这个项目**：

> **「每天几条，够用了」** —— 这本书不要求你一夜之间改变人生，它一次只给你十条。

母题的视觉转译方向：把「十条」做成**可数、可感知的物理存在**——像一份手写的便签、一张撕下来的卡片、一沓里抽出十张、每日翻页。而不是做成一个普通的网格列表。

各方向可以有不同的转译方式，这是三版的主要差异点之一。

## 8. form 推导五问（各方向自己作答，但答案供参考）

- **叙事角色**：首页 = hero + 内容入口。「每日十条」是 hero，其余是目录
- **观众距离**：手机 10cm（易读优先、字要大）/ 桌面 1m（密度可稍高、信息架构优先）
- **视觉温度**：温柔（不是冷静、不是兴奋）
- **容量估算**：手机首屏 844px 内要装下：顶栏 + 每日十条的标题区 + 至少 1.5 张完整卡片
- **视觉母题**：见第 7 节
